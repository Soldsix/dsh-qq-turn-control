# dsh-qq-turn-control

[English](README.md) | 中文

## 概要

本开发插件识别同一账号、同一会话中对机器人已成功发送消息的有效引用，其他消息交回聊天插件的既有策略。原生设置页可以控制提供方，不需要接入真实 QQ 账号。不引用时的多人话题判断、其他机器人识别和自动对话降频仍未完成。

<a id="use-and-limits"></a>
## 使用与限制

本 bundle 需要 DSH 0.2.2-rc.1、dsh-im-kit 0.2.0 和尚未发行的 dsh-qq-chat 0.2.0-development 接入分支。它添加所有者设置控制器和运行条目；策略默认关闭。在 DSH Web 中打开该 bundle，启用引用接话并保存。同一页面可配置引用有效时间（毫秒）、会话数量上限和每个会话保留的回复 ID 数量。已有其他接话策略占用服务时，启用会失败。

只有模型完成且发送收据确认接受的回复才进入有界内存索引。其他群或账号的结果、发送状态不确定的结果以及未知回复 ID 均不会匹配。保存设置或重启策略会清空索引。群消息明确指向机器人及私聊继续按 Chat 插件原有规则处理。策略缺失或失败时回退到原有规则，失败会发出本地诊断。

<a id="testing-and-privacy"></a>
## 测试与隐私

`npm test` 构建软件包并运行本地合成接话和控制器测试。`npm run test:native -- --im-kit-archive <library.tgz> --chat-archive <chat.tgz>` 将独立软件包安装到隔离 DSH SDK profile，使用受控本地模型端点。测试不发送 QQ 消息。原生检查覆盖引用追问、跨群隔离、明确寻址和重复消息抑制，不能据此证明真实 QQ 投送或自然对话质量。

策略不存储消息正文，也不发送模型可见提示词。请单独保护 profile 和 Chat 日志。隔离无头 Web profile 已验证设置保存及明暗、窄屏布局。Linux 与桌面端、真实 QQ 通道及不带引用的多人场景仍需验证。本开发版不是发行候选。
