# 多人接话控制

## 变更

由分类器或 Chat 基础规则选中的自动接话默认每群每 60 秒最多预留 3 次自动回复尝试，至少间隔 8 秒。`default` 转为忽略。普通成员明确 @ 和已识别的机器人回答引用不受此额度限制。已知引用或 @ 其他成员时直接忽略，不调用分类器。可选分类器会收到有限的引用原文和机器人回答的收件人别名。

`botIds` 中的机器人分别受发送者及群额度限制，包括明确 @；其未明确寻址的消息直接忽略。不提供自动机器人身份识别。生成或发送失败仍消耗预留额度。状态是临时的，在淘汰、过期、设置重载或重启时重置。

## 迁移

1. 更新本 bundle 及其固定依赖 dsh-qq-chat 0.2.3。Chat 需要支持 `ChatTurnPolicy.guard()` 和 `allowReply()`；旧版 Chat 无法执行完整的回复额度。
2. 在原生 bundle 页面检查 `ambientWindowMs`、`minAmbientGapMs` 和 `maxAmbientReplies`。最大次数为零时仅允许明确寻址；间隔为零时取消间隔要求。普通成员明确 @ 和已识别引用仍放行。
3. 将其他机器人经过认证的发送者 ID 填入 `botIds`，检查 `botWindowMs`、`maxBotReplies` 和 `maxBotGroupReplies`。不要从昵称或用户文字推断身份。
4. 保存后测试 A 询问机器人、B 质疑该回答、B 引用其他成员，以及机器人并发 @。不需要迁移人设、SQLite、持久化 Session、归档或记忆。本包控制 Chat 回复，不控制独立调度的媒体发送。
